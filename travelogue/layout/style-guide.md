# Travelogue Layout Style Guide

**Status:** ACCEPTED BASELINE  
**Approved:** 2026-09-21  
**Source trial:** 2026-08-02 to 2026-08-04, five A3 landscape spreads

この文書は、8/2〜8/4の試作で人間が承認したレイアウトを、残りの日程へ展開するための基準とする。

## 1. Page format

- 1ページ: A4 縦
- 1見開き: A3 横相当
- 見開き中央: 210 mm
- 外周安全余白: 約12 mmを基準
- 重要な顔・本文・写真キャプションは中央折りにかけない
- 最終塗り足しは印刷サービス決定後に調整する

## 2. Spread allocation

ページ数を日付単位で固定しない。

判断基準:
- 本文量
- 写真量
- 記憶上の重要度
- 一つの見開きで扱えるテーマ数

8/2〜8/4試作で確認した目安:
- 約600字 + 写真5〜7枚: 1見開きで成立しうる
- 約850字以上で複数テーマがある場合: 2見開きを優先
- 約1,100字以上で展示・感情・会話などテーマが分かれる場合: 2見開き以上を優先

文字を小さくして1見開きへ押し込むより、見開きを増やす。

## 3. Visual hierarchy

各見開きに原則1枚、視覚上の主役写真を置く。

基本構成:
- 主役写真: 1枚
- 準主役: 1〜2枚
- 小写真: 2〜4枚
- 本文ブロック: 1〜3個
- 必要に応じて短いコールアウト

小写真を均等に多数並べ、写真一覧のように見せない。

## 4. Narrative order

基本は左から右へ時間・体験が進む構成とする。

ただし、時間順よりも記憶の意味が強い場合は、
- 見たもの
- 感じたこと
- 語り合ったこと

など、テーマの流れを優先してよい。

## 5. Text

本文は千香視点を維持する。

優先順位:
1. 千香が実際に感じたこと
2. 後で記憶を呼び戻す出来事
3. 人との会話
4. 場所・展示・移動の説明

写真がない重要な出来事は削らず、本文またはコールアウトで残す。

写真の説明だけで本文を消費しない。

## 6. Captions

キャプションは写真を見れば分かることの繰り返しを避ける。

補う情報:
- 日付
- 場所
- 人物
- 状況
- 写真単独では分からない旅行中の意味

試作中は写真IDを併記してよい。
最終版では写真IDを削除する。

未確認事項は断定しない。

## 7. Photo workflow

制作時:
- Google Drive上のpreviewで選定・レイアウト
- Contact Sheetで一次選定
- 個別previewで詳細確認

印刷時:
- 採用写真IDから原本へ戻す
- Google Photos側の高解像度原本へ差し替える

Gitには原則として写真原本を保存しない。

## 8. Image handling

- 写真の縦横比を崩さない
- 主役写真は十分な面積を確保する
- 人物の顔を折り位置・裁ち落とし付近へ置かない
- 同じ場面の類似写真を複数置きすぎない
- 写真の技術的品質より、記憶を呼び戻す価値を優先する

## 9. Typography

8/2〜8/4試作の文字サイズ感を基準とする。

- タイトル: 24〜32 pt相当
- 本文: 9〜11 pt相当
- キャプション: 7〜8.5 pt相当

本文を9 pt未満へ縮小して収める必要がある場合は、先にページ分割を検討する。

最終印刷PDFでは日本語フォントを埋め込む。
試作用CIDフォントPDFを最終印刷データとして使用しない。

## 10. Revisit conditions

この基準は、単に別案を試したくなったことを理由に再検討しない。

再評価する条件:
- 実際の本文・写真が基準レイアウトに収まらない
- 印刷サービスの仕様により変更が必要
- 原本差し替えで重大なトリミング問題が発生
- 人間が明確にレイアウト変更を指定
- 8/2〜8/4試作では確認できなかった重大な制作上の問題が発見された

それ以外は、このスタイルを使って残りの日程の制作を進める。
